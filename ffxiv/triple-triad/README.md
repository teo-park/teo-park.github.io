# 트리플 트라이어드 수첩

공개 주소: <https://teo-park.github.io/ffxiv/triple-triad/>

카드 수집 체크, 한국어·초성·영문·번호·NPC·지역 검색, 미수집/획득 방법/등급/유형 필터, 모든 획득 경로와 선행 조건, 보유 카드에 기반한 규칙별 덱 추천을 제공합니다. 모든 기능은 무료이며 광고·후원·계정 연동이 없습니다.

## 데이터 범위

2026-09-07 확인 기준 FFXIV Collect 공개 API에 등재된 **475종(일반 460종, EX 15종), 획득 경로 695개, 대결 NPC 134명**을 포함합니다. API가 반환한 전체 개수와 실제 레코드 개수를 검증합니다. 이는 해당 공개 자료의 스냅샷이며 앞으로 추가되는 모든 카드나 국내 서버의 현재 획득 가능 여부를 보장하는 실시간 목록은 아닙니다.

- 카드: 고유 ID, 게임 내 No./EX 번호, 한국어/영문 이름, 패치, 별 등급, 유형 ID/이름, 상·우·하·좌 숫자, 이미지와 출처 링크.
- 획득: NPC 대결, 던전/토벌전/레이드, 교환, 카드팩, 업적, 퀘스트, 돌발임무 등 API의 모든 획득 경로. NPC 좌표·선행 퀘스트·대결 규칙, 원문에 명시된 교환 비용·우호도 등도 보관합니다. 공개 자료에 없는 드롭 확률이나 선행 조건은 추측해서 추가하지 않습니다.
- 한국어: 카드 475종 전체의 이름을 한국어 게임 시트에서 연결하고, 네 방향 숫자·등급·유형은 Collect와 한국어 `TripleTriadCardResident` 시트를 전수 대조합니다. 명칭 매핑 시 같은 행 ID를 이용합니다.
- 한국 공식 카드 상세 페이지 464종을 정확히 연결합니다. 나머지 11종은 검색 링크임을 명시합니다. 상세 페이지 미연결은 국내 미출시 판정을 뜻하지 않습니다. `(창천의 이슈가르드)`와 아이템 이름 `(창천)`은 명시적으로 연결합니다.
- 게임 내 카드 설명·인물 설정 등 장문 텍스트는 포함하지 않습니다. 이미지 파일을 복제하지 않고 FFXIV Collect의 공개 이미지 URL을 표시합니다. 외부 이미지 제공이 중단되어도 이름·숫자·획득처와 수집 기능은 사용할 수 있습니다.

## 추천 방식과 한계

5장 중복 금지, ★5 최대 1장, ★4와 ★5 합계 최대 2장 제한을 지킵니다. 기본적으로 체크한 보유 카드만 사용하고, ‘미수집 카드도 포함’은 전체 목록에서 목표 덱을 제안합니다.

1. 공개 카드의 방향별 숫자 분포를 상대가 특정되지 않은 비교 기준으로 사용합니다. 카드 숫자가 잡을 수 있는 면과 잡히지 않는 면을 평가합니다. 이는 승률이 아닙니다.
2. 서로 다른 카드가 네 모서리를 담당하도록 배치 가능성을 평가하고, 중앙 대응력과 노출되는 면의 균형을 함께 봅니다.
3. 역전과 에이스 약화의 1/A 예외를 실제 숫자 비교에 적용합니다. 유형 강화/약화는 유형 없는 카드를 제외하고 1~A로 제한합니다. 유형 효과 이전 35%, 덱 안 같은 유형 카드가 1~N장 놓인 경우 전체 65%를 평가하는 휴리스틱입니다. 상대의 같은 유형 카드는 모른다고 가정합니다.
4. 동수/합산은 상대 숫자 분포에서 두 면이 일치하거나 같은 합이 되는 연결 가능성을 작은 보조 점수로 사용합니다. 현재 판, 실제 포획·연쇄, 상대 NPC의 고정/가변 덱, 착수 탐색은 구현하지 않았습니다.
5. 무작위 순서/카드 교환은 방향별 균형의 가중치를 높입니다. 순서대로는 모서리 활용도가 높은 카드를 앞쪽으로 정렬합니다. 모두 공개/3장 공개/연장전은 수치 가중치를 바꾸지 않고 활용법을 안내합니다.
6. 무작위 규칙은 실제 추첨 결과를 입력하도록 요청합니다. 무작위 패와 카드 선발에서는 사전 보유 덱이 적용되지 않으므로 추천하지 않습니다.

유형·등급·모서리별 후보를 모아 폭 48의 빔 탐색을 한 뒤, 전체 후보를 대상으로 카드 한 장 교체를 두 번 개선합니다. 완전 탐색이나 최적 덱 보장이 아닌, 설명 가능한 출발용 추천입니다. 추천 이유에 표시한 모서리는 카드 단독의 적합한 방향이며, 고정된 최적 착수 지시는 아닙니다.

## 수집 기록

브라우저 `localStorage` 키는 `teo-ffxiv.triple-triad.collection.v1`입니다. 서버로 전송하지 않습니다. 기기·브라우저·접속 주소가 달라지면 별도 기록이므로 파일 내보내기/가져오기로 옮깁니다.

```json
{
  "type": "ffxiv-triple-triad",
  "schemaVersion": 1,
  "exportedAt": "2026-09-07T00:00:00.000Z",
  "collected": [1, 3, 6, 7, 10]
}
```

`collected`는 화면의 No. 번호가 아닌 **Collect/게임 시트의 고유 카드 ID**입니다. 파일은 전체 검증 후 적용하고 기본 동작은 기존 기록과 합치기입니다. 사용자가 선택한 경우에만 교체합니다. 현재 데이터에 없는 향후 ID도 보존하되 현재 수집률과 덱 후보에서는 제외합니다. 다른 수집 도구의 단순 숫자 배열은 번호 체계 혼동을 피하기 위해 받지 않습니다.

### 게임 캡처로 일괄 등록

수집 기록 관리 → **게임 캡처로 일괄 등록**에서 PNG·JPG·WebP 여러 장을 선택합니다. 캡처는 브라우저 메모리에서만 처리하며 서버 전송·이미지 보관·외부 AI 호출을 하지 않습니다. 저장하는 값은 검토한 카드 ID뿐입니다.

1. 게임 수첩을 **번호순 전체 목록**으로 놓고 페이지별로 캡처합니다. 보유 카드만 표시하거나 검색한 목록은 사용할 수 없습니다. `?` 미수집 칸과 빈 마지막 행까지 포함한 **5열×6행** 영역이 필요합니다.
2. 파일명 순서로 일반 1~16페이지, EX 1페이지를 임시 지정합니다. 게임 페이지 번호를 자동으로 읽지는 않으므로 일부 페이지만 선택했거나 파일 순서가 다르면 각 캡처의 페이지를 수정합니다. 현재 자료는 일반 460장·EX 15장입니다.
3. 첫 캡처에서 카드 목록만 드래그해 지정합니다. 위 페이지 번호와 아래 합계는 제외합니다. 같은 크기·위치로 찍었다면 ‘이 영역을 모든 캡처에 적용’으로 한 번에 맞춥니다. 숫자 입력으로도 영역을 조절할 수 있습니다.
4. 전체 인식 후 각 칸을 눌러 보유·미수집을 수정하고 페이지마다 확인 체크를 합니다. 애매한 칸이나 페이지 중복이 남으면 저장할 수 없습니다. 전체 475장 영역을 넣었다면 게임에 표시된 보유 수(예: 230)와 합계도 비교할 수 있습니다.
5. 기본은 **보유 카드만 추가**입니다. ‘확인한 페이지를 캡처 상태로 맞추기’를 선택하면 그 페이지의 미수집 체크만 해제하며, 다른 페이지와 향후 카드 ID는 유지합니다.

인식기는 물음표 칸의 밝기 패턴을 위치·크기·기울기를 조금씩 바꿔 비교합니다. 카드 그림의 이름을 읽는 OCR이나 모든 UI 테마에서 검증된 인식기가 아닙니다. 다른 UI 테마·정렬·잘못 지정한 영역·심한 압축·모션 효과에서는 오인식할 수 있으므로 각 페이지 검토가 필수입니다. 일반 마지막 페이지와 EX 페이지는 데이터가 있는 10칸·15칸만 반영합니다.

제공된 256×341 샘플은 실제 브라우저 파일 선택 → 인식 → 저장까지 **보유 21장·미수집 9장**을 확인했습니다. 같은 샘플의 확대·축소·밝기 변경·JPEG 변형 5개에서도 동일했으며, 다른 페이지나 테마에 대한 정확도를 의미하지 않습니다. 사용자 캡처나 전체 픽셀 데이터는 저장소에 포함하지 않습니다.

웹 카드 목록도 한 페이지 30장입니다. 데스크톱·태블릿은 5열이며 좁은 휴대폰에서는 3열 또는 2열로 줄입니다.

## 개발·갱신·검증

정적 파일이므로 빌드나 npm 설치 없이 배포됩니다. 저장소 루트에서 `python -m http.server 4186 --bind 127.0.0.1` 후 `/ffxiv/triple-triad/`를 엽니다.

Node.js 20 이상에서:

```sh
# 저장소 루트
node ffxiv/triple-triad/scripts/update-data.mjs --refresh
# 새 도구 폴더에서 테스트 의존성 설치 후 검사
cd ffxiv/triple-triad
npm ci --ignore-scripts
npm test
```

`--refresh`를 생략하면 저장소 `.cache/triple-triad/`의 원본을 재사용합니다. 갱신기는 API 레코드 수, 공식 목록의 페이지/중복, 카드 수치·유형 일치를 검증하고 한국어 잔여 영문/공식 링크 미연결 목록을 `translation-review.json`으로 남깁니다. 신규 경로 유형이나 한국어·영문 수치 불일치는 자동 배포하지 않고 실패시켜 검토하게 합니다. `data.js`는 코드 리뷰 후 함께 커밋합니다.

테스트는 덱 편성 제한, 역전/에이스 약화, 유형 효과, 검색의 번호 혼동, 조합별 추천, 한글 조합 중 검색, 수집 저장 실패, 모바일 상세 동기화, 가져오기 합치기/교체와 잘못된 파일, 다른 탭의 저장 갱신을 확인합니다. 캡처 등록은 일반/EX 페이지와 실제 ID 매핑, 중복·미확인 칸 차단, 마지막 페이지의 빈칸 제외, 검토 후 합치기와 해당 페이지 교체, 저장 실패 시 기록 보존도 검사합니다.
